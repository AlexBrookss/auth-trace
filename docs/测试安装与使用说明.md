# auth-trace 测试使用说明

> 用途：记录桌面"鉴权/认证"弹窗出现时，**是哪个程序发起了什么鉴权请求**。
> 安装后无需任何操作，保持后台运行即可。

## 一、安装（约 1 分钟）

1. 把 `auth-trace_0.1.0_all.deb` 拷贝到测试机任意目录（如 `~/下载`）。
2. 打开终端执行：

   ```bash
   cd ~/下载
   sudo apt install ./auth-trace_0.1.0_all.deb
   ```

3. 为当前用户开启"桌面鉴权记录"（只需执行一次，以后开机自动生效）：

   ```bash
   systemctl --user enable --now auth-trace-session.service
   ```

## 二、验证是否正常（建议装完就做一次）

```bash
systemctl is-active auth-trace-system           # 应输出 active
systemctl --user is-active auth-trace-session   # 应输出 active
pkaction >/dev/null 2>&1; sleep 1; tail -n 2 /var/log/auth-trace/events.log
```

最后一条命令应能看到**一行带当前时间**的记录（含 `member=EnumerateActions` 或 `action=`）。

不 OK 时：

```bash
systemctl status auth-trace-system              # 看系统服务状态
journalctl -u auth-trace-system -n 20           # 看系统服务日志
journalctl --user -u auth-trace-session -n 20   # 看用户服务日志
```

## 三、复现问题时怎么做

1. 弹窗出现后，**记下大致时间（精确到分钟即可）**，能截图更好；
2. 让服务继续在后台跑，**不要卸载、不要删日志**；
3. 不需要其他操作。

## 四、把结果反馈给开发

执行（把 `15:20` 换成你记下的复现时间）：

```bash
sudo auth-trace-report "15:20"
```

会在 `/var/log/auth-trace/reports/` 下生成一份报告文件，把**最新的那个 `.txt` 文件**
发回给开发即可。

如果时间记不太准，可以放宽范围（前后各 10 分钟）：

```bash
sudo auth-trace-report "15:20" -w 10
```

也支持指定日期：

```bash
sudo auth-trace-report "2026-10-10 15:20" -w 5
```

反馈内容建议带齐：

1. 复现时间（如 `15:20`）
2. `/var/log/auth-trace/reports/` 里最新的 `.txt` 报告文件
3. （可选）弹窗截图、机型/系统版本（`cat /etc/os-version`）

## 五、常见问题

| 问题 | 解答 |
| --- | --- |
| 服务会自己弹窗吗？会影响桌面吗？ | 不会。它只监听、只记录，不触发任何鉴权行为。 |
| 重启电脑要重新设置吗？ | 不需要，两个服务都是开机/登录自启。 |
| 日志会占满硬盘吗？ | 不会，日志自动轮转（单文件上限 20MB，保留一代）。 |
| 忘了记时间怎么办？ | 越接近越好，报告支持 `-w` 放宽时间范围；或联系我们。 |
| 怎么卸载？ | `sudo apt remove auth-trace`（历史日志会保留）。 |
| 多个测试账户？ | 每个需要监控的账户各自执行一次第 3 步的 `systemctl --user enable --now ...`。 |
